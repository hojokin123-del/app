# business-os — AI業務改善キット

作成日: 2026-07-04（Claude Fable 5 による業務分析に基づく）

「申請書類の作成」を最大のボトルネックとして、提案 → ヒアリング → 申請書ドラフト → 提出前QA の流れを AI 化するための資産一式。

## 何がどこにあるか

| ファイル | 中身 | いつ使う |
|---|---|---|
| `00_業務マップ.md` | 業務の棚卸し（日次/週次/月次/単発）と AI 分担 | 業務を見直すとき・Claudeに前提を伝えるとき |
| `01_自動化候補と優先順位.md` | 改善案17個の評価と優先順位 | 次に何を作るか決めるとき |
| `02_運用ルール.md` | 命名規則・セキュリティ・AI利用ルール | 常時（⚠ 冒頭の緊急対応を必ず読む） |
| `checklists/申請書提出前QA.md` | 提出前チェックリスト | 申請書を提出する前 |
| `prompts/定型プロンプト集.md` | コピペ用プロンプト5本 | 公募要領差分・回収チェック・議事録など |
| `../tools/hojokin-navi.html` | 助成金提案ナビ（ミニWebアプリ） | 商談前・ヒアリング時 |
| `../.claude/skills/shinsei-draft/` | 申請書ドラフト生成 Skill | 申請書を書くとき（`/shinsei-draft`） |
| `../.claude/skills/teian-pack/` | 提案書・DM・商談台本 Skill | 営業文書を書くとき（`/teian-pack`） |
| `samples/` | Skill が生成したサンプル成果物 | 出力イメージの確認用 |

## 明日からの基本フロー（申請1件の流れ）

1. **商談・ヒアリング**: `tools/hojokin-navi.html` をブラウザで開き（ダブルクリックでOK、ネット不要）、顧客情報と施策を入力 → タイムスケジュールCSVを顧客シートに取り込み、「Claude用ヒアリングテキスト」をコピー
2. **ドラフト作成**: Claude Code で `/shinsei-draft` を呼び、ヒアリングテキスト＋最新の公募要領（PDF/URL）を渡す → 30分後にドラフトができる
3. **レビュー**: 【要確認】マークと「不足情報リスト」を潰す（ここが人間の仕事）
4. **提出前**: `checklists/申請書提出前QA.md` を消化（★印はClaudeに自動チェックさせてよい）
5. **提出後**: 採択されたら申請書を匿名化して `knowledge/` に保存（次回の精度が上がる）

## 鉄の掟

- AI の出力は常に**下書き**。提出・送信・請求は人間が行う
- 金額・要件は公募要領の**原文**で最終確認
- パスワードをスプレッドシートに書かない（`02_運用ルール.md` 参照）
