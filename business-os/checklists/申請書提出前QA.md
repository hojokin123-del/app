# 申請書 提出前QAチェックリスト

使い方: 提出前に人間がチェック。Claudeにドラフトと一緒に渡すと機械的な項目（★印）は自動チェックできる。

## 1. 要件適合（不採択・不支給の直接原因）
- [ ] 申請者は対象者要件を満たすか（従業員数・資本金・業種・地域）
- [ ] 対象経費のみ計上されているか（対象外経費の混入なし）
- [ ] 事業実施期間内に発注・支払が収まるスケジュールか
- [ ] 過去の同一制度の受給歴・併給調整を確認したか（例: 支給決定済みの訓練は申請不可）
- [ ] 就業規則・雇用契約など前提書類の整備状況を確認したか

## 2. 数値整合 ★Claudeで自動チェック可
- [ ] 経費明細の「単価×回数」と金額欄が一致する
- [ ] 小計・合計・補助金交付申請額の計算が合う
- [ ] 補助率・上限額を超えていない（例: ウェブサイト関連費は申請額合計の1/4以内）
- [ ] 税抜/税込の選択が事業者区分（課税/免税）と一致
- [ ] 本文中の金額・人数・日付が様式間で矛盾しない

## 3. 記載品質 ★Claudeで自動チェック可
- [ ] 【要確認】マークが残っていない
- [ ] 会社名・代表者名・所在地が正式表記（登記どおり）
- [ ] 誤字脱字、旧制度名の残骸がない
- [ ] 審査項目（加点項目）に対応する記載があるか

## 4. 添付書類
- [ ] 公募要領の添付書類リストと突き合わせた（見積書、決算書、登記簿、賃金台帳など）
- [ ] 見積書の有効期限・宛名・相見積ルールを確認
- [ ] GビズIDの有効性を確認（取得に2〜3週間かかる）

## 5. 提出直前
- [ ] 顧客の最終承認を得た（メール等で記録に残す）
- [ ] 締切日時と提出方法（jGrants/郵送/窓口）を公募要領原文で再確認
- [ ] 提出データのファイル名が命名規則どおり（02_運用ルール.md）
- [ ] 控え一式を顧客フォルダに保存した
